## 二、四个必须认清的坑

### 1. 英文原名同时是数据主键

这是最关键的一条。看 `js/data.js`：

```js
const jobBaseData = { "Knight": { name: "Knight", ... } }
const requirementsBaseData = { "Knight": [...] }      // 需求表用同名做 key
```

再看 `js/ui.js`：

```js
row.id = "row" + toId(name)          // DOM id 由名字生成
tooltip.setAttribute('data-name', name)  // tooltip 反查也靠它
```

**所以绝对不能"直接把名字改成中文"**——存档里的 `savedMaxLevels`、`requirements`、`completed_requirements` 全都会对不上，老存档直接报废。

正确做法：英文名永远是 key，只在"往屏幕上写"的那一刻翻译。本方案里的 `I18N.n(name)` 就是干这个的。

### 2. 大量句子被行内标签切开

```html
<div>Multiplies <span class="color-happiness">Happiness</span> by x<span>2</span></div>
```

渲染出来的文本节点是 `"Multiplies "`、`"Happiness"`、`" by x"`、`"2"` 四段。中文语序不同，逐段翻译会拼出病句。

处理策略分两档：

- **语序兼容的**（`"You have spent" + 数字 + "years"` → `"你已度过" + 数字 + "年"`）：逐段翻没问题，已用词表覆盖。
- **语序冲突的**（`", but divide" + 数字 + "gain by x"`）：必须整块替换，用 `data-i18n-block="键名"` 标记容器 + `lore` 词表整块换 `innerHTML`。

### 3. `<template>` 不在文档树里

表头 `Level / Max / Value type / On / Effect / Expense` 来自 `<template>`。`document.body.querySelectorAll` **扫不到** template 内容，必须单独遍历 `template.content`。

### 4. 渲染有缓存

`js/ui_cache.js` 的 `safeUpdateText` 会用 `uiCache.text` 做脏检查：文本没变就不写 DOM。所以语言必须在**第一次渲染之前**就定下来，否则缓存里存的是旧语言，切换后不刷新。本方案直接用 `location.reload()` 切换，绕开这个问题。

## 三、已实现的架构

```
js/lang/zh-CN.js   词表（纯数据，加语言只需新增一个文件）
js/i18n.js         引擎（t/n/d/lore/f + 静态 DOM 扫描 + 语言切换）
css/lang-zh.css    中文字体栈，仅在 <html lang="zh-CN"> 时生效
```

### 四个取词函数

| 函数 | 用途 | 例 |
|---|---|---|
| `I18N.t(key, fallback)` | 界面固定词条 | `I18N.t("Income", "Income")` → `收入` |
| `I18N.n(name)` | 实体显示名，英文原名作 key | `I18N.n("Knight")` → `骑士` |
| `I18N.d(text)` | 短描述 | `I18N.d("Skill XP")` → `技能经验` |
| `I18N.lore(key, fallback)` | 长工具提示正文 | 未收录时原样返回英文 |
| `I18N.f(key, fb, vars)` | 模板插值 | `I18N.f("age_days", ..., {age:14, day:0})` |

**全部带兜底**：词表缺条目时返回英文，不会抛错，也不会显示成 `undefined`。

### 静态文本的零侵入翻译

`I18N.apply()` 在脚本加载时扫一遍 `document.body` 的文本节点和 `placeholder / title / alt / data-short` 属性，用**整节点精确匹配**（先去空白归一化）查表替换。匹配不上就原样保留——所以不会误伤数字、金额、动态内容。

好处：`index.html` 一行不用改就能翻 200+ 条静态文案。坏处：只对"整节点就是一句完整话"的情况有效。

### 语言切换

设置 → 界面设置 → 语言。写 `localStorage.pk_quest_language` 和 `gameData.settings.language`（跟着存档走），然后整页重载。首次进入按 `navigator.language` 自动判断。

## 五、当前覆盖度

词表 **1003 条**（ui 172 / names 245 / desc 63 / static 313 / lore 210，另加中文更新日志），扫描结果：页面剩余英文 **33 处**，且都不是需要翻译的内容——

- `MPP` / `EPP`：游戏术语缩写，保留
- `1.00Mp` / `500.0kp` 之类：货币数值后缀，不译
- `Chairman lvl 1227`：HTML 里的占位文本，运行时会立刻被替换
- `Ihtasham42`：原作者署名

即**可见文案已全部汉化**。整块替换（`data-i18n-block`）覆盖了：

| 块 | 键 |
|---|---|
| 护符页 8 段叙述（含嵌套的"超越"按钮、全部数字 span） | `block:rebirth0..5,7,8` |
| 暗物质能力 10 处负面效果 | `block:neg0..9` |
| 重置能力提示 | `block:resetHint` |

自测工具（在 `tools/`，需先 `npm i jsdom`）：

```bash
node tools/coverage.js       # 扫静态 DOM：遍历所有主标签/子标签，再推入终局状态走第二遍
node tools/tooltip-audit.js  # 把每种 tooltip 真实渲染两遍（新存档 + 终局）再扫
node tools/smoke-test.js     # 启动游戏，抓运行时错误 + 抽样渲染文本
```

三个脚本都支持 `PK_LANG=en` 环境变量，用来跑英文回归。

**为什么要跑多遍**：很多文本只在特定分支出现。

1. **分支态**：需求 tooltip 分"进行中"和"已完成"两条渲染路径，只跑新存档永远看不到后者；元宇、暗物质能力、英雄相关面板同理。
2. **id 拼出来的文本**：挑战标题由 `getFormattedTitle("rich_and_the_poor")` 生成，会变成 `Rich and the poor`（**丢掉冠词 The**），和词表里的 `The rich and the poor` 对不上。`tooltip-audit.js` 第三遍会遍历 `gameData.challenges`，逐个验 `getFormattedTitle` 产物并渲染侧栏整块。

`getFormattedTitle` 已改为**先按原始 id 查表，再转标题查表**，类名映射两套都收。

**currency 后缀不译**：`p/g/s/c`（pence/gold/silver/copper）是货币单位符号，跟 `k/M/B/T` 一样，保留原样。

## 六、顺手发现的两个问题

### 1. `js/events.js` 第 88 行有一段混淆代码

解混淆后是：

```js
(function () {
  const MO = window.MutationObserver;
  const ob = new MO(async (mutations, obs) => {
    const target = document.getElementById('errorElement');
    if (!target) return;
    obs.disconnect();
    const ratio = getRandomInt(hashCode('' + gameData.dark_orbs), hashCode('' + gameData.essence));
    applyCustomImage('./img/logos.png', ratio)
      .then(text => window.safeSetHTML(target, text))
      .catch(() => { target.innerHTML = "<div>Sorry, something went wrong. But you're amazing!</div>"; });
  });
  ob.observe(document.body, { childList: true, subtree: true });
  if (typeof window.activateAntidote === 'function') window.activateAntidote(MutationObserver);
})();
```

`applyCustomImage`（`js/utils.js:524`）会把 `img/logos.png` 的像素最低位当比特流解出来，用玩家状态算密钥解密成 **HTML 字符串**，再 `innerHTML` 塞进页面。

- 目前 **`#errorElement` 这个元素不存在**，所以这段是死代码，不生效。
- 但它本质上是一条"图片隐写 → 注入 HTML"的通道。只要哪天页面里出现了 `id="errorElement"`，`logos.png` 一换，就能往页面里注入任意 `<img onerror=...>` 这类可执行内容。
- 建议：汉化版直接删掉这一行，或至少不要从不可信来源替换 `logos.png`。

### 2. `js/game.js` 里的 `_0xsys` 数组

```js
const _0xsys = ['\x65\x73\x73\x65\x6e\x63\x65', '\x69\x73\x46\x69\x6e\x69\x74\x65', '\x70\x6f\x77', '\x31\x30', '\x33\x30\x38'];
// 解出来就是 essence / isFinite / pow / 10 / 308
```

只是把 `gameData.essence >= 1e308` 这种判断拆成数组 + 十六进制字符串，属于原作者防改的写法，无实际危害，可以不管。
